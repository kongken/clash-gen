# Domain docs

This repository uses a single-context layout. Before exploring the codebase, read the root `GLOSSARY.md` and any relevant ADRs in `docs/adr/`. If either is absent, proceed silently. The `domain-modeling` skill adds glossary entries and ADRs as terms and decisions are settled.

## Use the glossary's vocabulary

Use the glossary's terms in issue titles, refactor proposals, hypotheses, and test names. If a term is missing, check how the project names the concept and flag any genuine gap for `domain-modeling`.

## Flag ADR conflicts

If a proposal contradicts an existing ADR, name the ADR and explain why the decision might need to be revisited.
